## 2. 严重问题（3 个，均已人工复核证实）

### S1. ⌥R 原位替换功能失效
- 文件：`Sources/OmniTrans/Services/TextReplacementService.swift:49`
- 问题：自身 `clearContents()+setString()` 已使 `changeCount` 递增，轮询首轮即判定"目标已消费"并恢复旧剪贴板；而模拟 Cmd+V 是异步投递，恢复几乎必然抢先 → 目标应用粘贴旧内容。且检测前提本身错误：**粘贴读取剪贴板不会改变 changeCount**（只有写入会）。
- 背景：2026-08 审计 B1 将主线程自旋改为 async，但核心判定逻辑未修正。
- 建议：放弃 changeCount 消费检测；改为「写入后基线 + 短宽限期（~0.5s）+ 第三方写入检测（若期间他人写入则不恢复）」；恢复写入前再次抑制剪贴板监控。

### S2. OCR 首帧等待取消竞态 → 子系统死锁
- 文件：`Sources/OmniTrans/OCR/Capture/ScreenRegionCapturing.swift:284-292`
- 问题：任务已取消时 `onCancel` 先耗尽 OnceGate（此时 continuation 尚未存入），continuation 随后存入却永不被 resume；`withThrowingTaskGroup` 隐式等待所有子任务 → 捕获永久挂起并占用 ActiveStreamGate 槽位，后续 OCR 全部死锁。代际接管取消可触发。
- 建议：以「continuation 槽 + 锁」本身作为恰好一次恢复机制（取代 OnceGate），并在存入后立即检查 `Task.isCancelled` 补恢复。

### S3. Keychain 迁移失败后密钥静默丢失
- 文件：`Sources/OmniTrans/Utils/KeychainManager.swift:244`（配合 :264）
- 问题：`defer` 无条件置 `migrationDone=true`，在 else 分支 `set(false)` 之后执行并覆盖；部分迁移失败后永不重试，而 Keychain 后端只读 Keychain 不回读旧文件 → 未迁移 provider 的密钥静默丢失。注释声称"仍可经 fallback 路径读取"与实际不符（fallback 仅在 Keychain 探测失败时启用，彼时根本不会迁移）。
- 建议：移除 defer，各路径显式置标记；batchReadAll 在旧文件仍存在时合并读取缺失条目（防御纵深）。

## 7. 亮点

1. 密钥全走 header（Bearer/x-api-key/x-goog-api-key），无 URL 带 key、无 TLS 绕过；签名统一 RFC3986 单次编码。
2. 弃管式超时 + OnceGate 恰好一次 resume + 闸门/熔断，OCR 抗停滞体系完整且注释附真机证据；DisplayGeometry 纯函数坐标层配 12 个多屏测试；捕获零拷贝 BGRA 直通。
3. ThrottledStream actor 隔离 + 首块直通 + 自适应批处理；SSE 解码连续失败 8 次即中止并记日志；重试有界（2 次 + 抖动 + 鉴权过滤）。
4. AnimationToken 语义化动效体系，reduce-motion 与全局门控双降级；热键路径 debounce + 捕获移出主线程 + TLS 预连接重叠，延迟设计考究。
5. 无明文密钥落盘、AES-GCM nonce 随机、secrets 文件原子写 + 0600、内存/IO 全有界。
