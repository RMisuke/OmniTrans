## 一、OCR 链路（重点优化）

### A1. SCShareableContent 缓存 ⭐ 最大收益
- **问题**：每次 OCR 截图都重新执行 `SCShareableContent.current` —— ScreenCaptureKit 最昂贵的调用之一，需向 WindowServer 枚举全部窗口/显示器，典型耗时 **100–500ms**，是框选松开到出字延迟的最大来源。
- **修复**：新增 `SCShareableContentCache`（actor）。首次捕获后缓存，显示器拓扑变化（`didChangeScreenParametersNotification`）立即失效，另有 30s TTL 兜底。后续捕获命中缓存为亚毫秒级。
- **文件**：`Services/CaptureService.swift`
- **预期收益**：OCR 端到端延迟减少 100–500ms（首次之后）。

### A2. 死代码清理
- `attemptOCR` 的 timeout 参数所有调用点均传 `nil`，为死路径 —— 已移除参数及 `ResumeOnceGate` 门控（硬件探测路径的超时门控保留在 `OCRHardwareMode.swift`）。
- **文件**：`Services/OCRSelectionOverlay.swift`

### A3. 热路径日志降级
- OCR 链路 26 处 `print()`（stdout 同步 I/O）全部改为统一 subsystem 的 `os_log(.debug)`，Release 下零持久化开销。
- **文件**：`CaptureService.swift`、`OCRSelectionOverlay.swift`、`OCRHardwareMode.swift`、`SettingsPanelContent.swift`

### A4. 双重 purge 修复
- `dismiss()` 原来在主队列与后台队列各调度一次 `purgeBackendCache()`（后台那次又 hop 回 MainActor），实际执行两次全量清理。现只保留一次，延迟到下一 runloop 执行，避免拖慢结果弹窗首帧。

## 二、Bug 修复

### B1. ESC 取消框选失效
- **问题**：overlay 使用原生 `.borderless NSWindow`，其 `canBecomeKey` 默认返回 `false` → overlay 永远无法成为 key window → ESC 的 `keyDown` 收不到事件，用户无法取消框选。
- **修复**：新增 `KeyableBorderlessWindow` 子类（`canBecomeKey = true`）。
- **文件**：`Services/OCRSelectionOverlay.swift`

### B2. ⌥R 原位替换自触发翻译
- **问题**：替换文本短暂进入系统剪贴板；若开启剪贴板监控，`ClipboardMonitor` 会把它当作新划词再翻译一次。
- **修复**：`replaceSelectedText` 写入剪贴板前设置 `ClipboardMonitor.shared.suppressNext = true`。

### B3. 启动诊断门控
- `DisplayLayoutDebug.dump()`（多屏布局诊断输出）原在每次正式启动无条件运行，现仅在 `#if DEBUG` 构建。

### B4. 历史归档内存尖峰
- **问题**：`HistoryActor.rewriteArchive` 无 limit 全量解码 JSONL 后再截断，数万条历史时产生明显内存峰值。
- **修复**：`loadFromArchive(limit:)` 升级为流式滑动窗口 —— 解码过程中只保留最新 `limit` 条，更旧行即时丢弃，内存占用从 O(文件大小) 降为 O(cap)。
- **文件**：`Services/HistoryActor.swift`

## 三、启动速度

### C1. 移除占位窗口 hack
- **问题**：SwiftUI `WindowGroup` 创建 0×0 占位窗口，启动后在 `hidePlaceholderWindow()` 中遍历查找并关闭 —— 多余的窗口创建 + 遍历 + 潜在闪烁。
- **修复**：场景改为 `Settings { EmptyView() }`（仅用户打开时才实例化窗口），删除 `hidePlaceholderWindow()`。accessory 菜单栏应用启动时零窗口。

### C2. 删除低价值预热
- 移除 `MacOSNativeProvider.prewarmCache()`（"hello/world/the" 等常见词预热对真实查询命中率≈0）。词典缓存按需填充。

### C3. OCR 硬件探测惰性化
- **问题**：探测最多两轮 × 3s 超时占用 ANE，虽异步但与启动争抢资源。
- **修复**：改为首次 OCR 触发时执行（`runIfNeeded()` 幂等），与用户拖拽框选时间重叠；探测完成前 fallback `.fast` 安全模式，行为语义不变。

## 四、安全加固

### S1. 密钥存储迁移到真 Keychain ⭐
- **问题**：原方案 AES 密钥由 IOPlatformUUID + 硬编码盐派生 —— 本机任意进程无特权即可读取该 UUID，加密仅为混淆强度。
- **修复**：`KeychainManager` 重写为双后端：
  - **首选 macOS Keychain**：每 provider 一条 GenericPassword（service=`com.omnitrans.secrets`），由 securityd 保护；
  - **回退加密文件**：Keychain 探测失败（如无签名标识环境）时保持旧 AES 方案，数据不丢；
  - **自动迁移**：首次访问检测旧 `secrets.json`，解密迁入 Keychain 后删除明文残留；部分失败保留旧文件可重试。
- **文件**：`Utils/KeychainManager.swift`

### S2. secrets.json 权限收紧
- 回退路径写入文件后显式 `chmod 0600`（owner-only 读写），防同机其它用户读取。

### S3. 网络日志隐私脱敏
- `NetworkLogger.logRequest/logResponse` 的请求/响应体预览可能含用户翻译文本 —— 改为仅 `#if DEBUG` 记录 body；Release 只记方法与 URL。
